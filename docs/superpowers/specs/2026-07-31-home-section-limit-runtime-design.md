# 首页展示数量配置生效设计

## 目标

让系统管理后台“首页展示”中的五个数量严格控制新版公开首页，并将第一项的界面名称从“今日推荐”改为“排行榜数量”。

## 现状与根因

后台已将五个值保存在 `marketing_billing.home_section_limits` 中，但新版首页服务存在两层硬编码覆盖：

- `ranking_preview` 始终查询并截取 10 条，没有使用 `home_section_limits.today_pick` 的展示值。
- 长期稳定、性价比、新入榜和风险预警会被强制扩大到至少 4 条，导致后台设为 1–3 时不能严格生效。

## 兼容策略

保留现有 `home_section_limits.today_pick` 存储键和 API 结构，仅将管理后台标签改为“排行榜数量”。这样无需数据库迁移，已保存的值也会继续有效。

新版首页将该键解释为排行榜预览数量：

1. 全量排行查询的 `pageSize` 使用 `today_pick` 配置。
2. `ranking_preview.items` 按同一配置截取。
3. 旧的 `sections.today_pick` 数据仍保留并使用同一数量，不破坏旧消费方。

其余四项直接使用后台配置，不再强制最少 4 条。

## 数据流

`AdminApp` 保存设置 → `MarketingSettingsService` 校验并持久化 `home_section_limits` → `PublicViewService.getHomePageView()` 读取配置 → 排行榜预览和四个摘要榜单按配置生成 → React 首页与 SSR 消费同一份首页视图。

## 边界与错误处理

- 继续使用现有 1–12 的整数校验。
- 旧配置缺失时继续使用现有默认值。
- 首页可用数据少于配置数量时，展示实际可用数据，不生成空占位。
- 不修改排序算法、评分、点击计费、广告位或新闻数量。

## 验证

- 服务层测试：配置“排行榜数量”后，确认查询 `pageSize` 和 `ranking_preview.items` 数量一致。
- 服务层测试：长期稳定、性价比、新入榜和风险预警分别按配置值截取。
- 管理端静态回归：界面显示“排行榜数量”，不再显示“今日推荐”。
- 运行聚焦测试和前端构建，确认 React 与 SSR 数据契约未破坏。
