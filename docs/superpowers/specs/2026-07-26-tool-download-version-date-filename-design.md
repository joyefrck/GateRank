# 工具下载版本、更新日期与原始文件名设计

## 目标

完善系统管理后台和公开工具下载页的版本、日期与文件名展示：

- 后台软件列表增加独立的“软件版本”列。
- 已发布软件编辑保存后，前台“发布”日期展示本次更新日期。
- 用户下载本地安装包时，最终文件名与后台上传时的原始文件名一致。

## 当前根因

- 后台列表已有 `version` 数据，但表格只展示了平台及其支持的系统版本。
- 前台信任信息优先使用首次发布时写入的 `published_at`，忽略了每次数据库更新自动变化的 `updated_at`。
- 上传流程已将 `original_name` 写入安装包旁的 `.meta.json` 文件，但下载服务仍通过软件名称、平台和版本重新生成下载文件名。

## 设计

### 后台软件版本列

将现有“平台与版本”表头明确为“平台与系统版本”，并在其后增加“软件版本”。单元格直接展示 `item.version`，空值展示 `—`。空列表行的 `colSpan` 同步增加，保持表格结构正确。

### 前台更新日期

`buildToolDownloadTrustMeta` 将 `updated_at` 作为日期第一来源，只有缺失时才回退到 `published_at`。文案继续使用“发布”，满足现有页面布局，同时让编辑保存后的日期立即反映最新更新日。

### 保留原始下载文件名

工具上传元数据继续作为原始文件名的唯一来源，不新增数据库字段或迁移：

1. 上传完成后，现有流程继续在安装包旁保存 `.meta.json`，其中包含 `original_name`。
2. 下载服务验证文件存在后，读取对应元数据并将 `original_name` 作为 `downloadFilename`。
3. 受控下载响应通过 `Content-Disposition` 返回该文件名，兼容应用直传和 Nginx `X-Accel-Redirect` 两条路径。
4. 前台下载链接不再声明二次生成的 `download` 文件名，最终名称统一由响应头决定。
5. 旧文件缺少元数据或元数据不可读时，回退到服务器实际文件名，不再按软件名、平台和版本二次拼接。

## 边界与安全

- 原始名称读取限定在工具安装包目录和对应元数据文件内。
- 响应头继续使用现有 `Content-Disposition` 编码函数，保留中文及非 ASCII 文件名支持，并生成安全的 ASCII 回退名。
- 不改变安装包磁盘存储名、公开受控下载 URL、下载计数或发布状态逻辑。
- 不对历史安装包做猜测性重命名；缺少上传元数据时只使用实际存储名。
