# GateRank 方法论页公开原则版设计说明

日期：2026-08-11
状态：已确认（方案 A）

## 目标

将 `/methodology` 从“公开评分实现细节”改为“公开评估原则”。页面继续帮助用户理解 GateRank 评什么、数据如何产生、怎样解读结果以及平台如何保持独立性，但不再披露可被直接复制或反向实现的模型参数。

## 对外公开边界

公开内容：

- S、P、N、C、R 五个评估维度的名称、目的和定性说明。
- 持续监测、真实代理请求、多地区采样、数据验证、结果聚合和异常复核等高层流程。
- 分数是多维综合结果，近期数据更重要，新机场需要积累有效样本，风险信号独立展示等原则。
- 历史快照、规则版本、非付费排名和结果可追溯等可信度说明。

不公开内容：

- 五维权重及任何加权公式。
- 子项公式、阈值、分段、线性插值和满分或零分边界。
- 风险事件的具体扣分值、封顶值和组合方式。
- 时间衰减参数、冷启动公式、有效天数边界和回退计算细节。
- 可用于复算结果的完整演算案例、内部变量名和参数表。

即使内容被折叠、隐藏或只用于 SEO，也不得把上述细节输出到客户端 HTML、SSR 页面、JSON-LD、FAQ 或机器可读描述中。

## 视觉方向

视觉命题：用克制、可信、编辑化的技术说明页呈现 GateRank 的评估原则，让信息看起来像独立评测机构的公开说明，而不是算法文档或营销落地页。

- 使用白色与浅灰背景、密集黑色标题、细边框和少量靛蓝语义强调。
- 移除当前大面积蓝色渐变、玻璃拟态统计块、公式代码框和过多嵌套卡片。
- 主内容最大宽度与站点公共页面保持一致，桌面端控制每行阅读长度，移动端保持单列顺序。
- 圆角、阴影和强调色保持克制；主要操作只保留一个近黑色 CTA。
- 所有交互保留清晰的 hover、focus-visible 和键盘访问状态，并尊重 reduced-motion。

## 页面信息架构

### 1. 首屏

- 眉题：`GATERANK METHODOLOGY`。
- H1：`我们如何评估一个机场`。
- 简介：说明 GateRank 通过持续采样与多维信号判断长期使用质量。
- 保密提示：`本页公开评估原则；模型参数、阈值与计算细节属于内部方法，不对外披露。`
- 三项非算法事实：五维观察、持续更新、历史可追溯。

### 2. 五维评估框架

以五个等权视觉卡片说明 S/P/N/C/R，但不展示权重或分数公式：

- S 稳定性：持续可用、波动和连续健康表现。
- P 性能：响应速度、传输能力和真实代理请求质量。
- N 网络覆盖：可检测节点的地区广度、健康情况和分布结构。
- C 性价比：价格、套餐能力与实际体验之间的匹配程度。
- R 风险：域名、证书、投诉和历史异常等独立信任信号。

### 3. 数据如何形成结果

采用四步线性流程：

1. 持续采集：从真实可检测节点和公开信息中获取样本。
2. 真实性验证：要求关键结果经过实际代理请求或一致性检查。
3. 多维聚合：降低单次高光、极端样本和单一指标的影响。
4. 异常复核：对采集缺失、突变和风险信号进行独立标记。

流程只说明方法，不展示内部实现、参数和决策阈值。

### 4. 如何理解 GateRank 结果

使用三段说明代替公式与演算案例：

- 看综合，不看单项：高速度或低价格都不能独立决定推荐。
- 看趋势，不看截图：近期变化与历史连续性共同提供判断背景。
- 看数据状态：样本不足、当日采集缺失或规则版本不同会明确提示。

### 5. 透明度边界

左右两列展示：

- 我们公开：维度定义、数据日期、趋势、风险来源类别、规则版本和历史快照。
- 我们保留：模型权重、阈值、扣分参数、抗操纵规则和风控细节。

说明保留内部参数是为了降低针对性优化、数据操纵和直接复制风险，并不影响用户查看实际结果与证据。

### 6. 可信度原则与 FAQ

可信度原则保留为：持续监测、真实请求、多维交叉、风险单列、历史留痕、非付费排名。

FAQ 只回答用户决策问题，例如低价是否一定高分、测速快是否一定推荐、新机场为何需要观察、风险分低意味着什么、数据多久更新。删除所有可复算权重、阈值、公式和插值方式的问题与答案。

### 7. 结尾行动

- 主 CTA：查看机场排行。
- 次级文本链接：查看最新报告。
- 结论强调长期可信与证据连续性，不再声称“公式公开”。

## React、SSR 与 SEO 一致性

- React 页面和 `publicPageRenderer` 的 SSR 输出必须拥有相同的标题、章节顺序、公开边界和核心文案。
- SEO title、description、keywords、FAQ JSON-LD 和其他机器可读属性不得包含权重、公式、阈值、扣分值、衰减参数或冷启动参数。
- SEO 保留“机场测评方法、评估维度、数据来源、风险监测、机场推荐依据”等用户意图词，避免以“公式、扣分规则、阈值”等泄密词作为页面卖点。
- OG 素材同步使用新标题和克制视觉，不展示任何公式。

## 响应式与可访问性

- 桌面端五维卡片允许 5 列或 3+2 布局；小屏改为单列或可读的两列，不使用横向滚动承载正文。
- 四步流程在桌面端横向排列，移动端转为纵向，并保留明确步骤顺序。
- FAQ 使用原生可访问折叠结构或等价语义，键盘与屏幕阅读器可操作。
- 正文对比度、字号、行高和焦点状态满足公共页面既有可访问性标准。

## 验收标准

- 页面和页面源代码中不再出现任何评分权重、计算公式、评分阈值、具体风险扣分、衰减参数、冷启动公式或可复算案例。
- 用户仍能清楚理解五维分别评什么、数据如何形成、结果应该怎样解读。
- React 与 SSR 文案、结构和 SEO 信息一致。
- 桌面与移动端无溢出、层级清晰，导航、FAQ 和 CTA 可正常操作。
- 更新相关前端、SSR、SEO 与路由测试，并通过定向测试、类型检查、lint、build 和 `git diff --check`。
