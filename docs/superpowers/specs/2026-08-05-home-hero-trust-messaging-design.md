# GateRank 首页 Hero 可信度信息设计

## 目标

在首页 Hero 现有高度内增加两条可信度信息，并保持 React 水合后页面与 SSR 首屏语义一致：

- `行业首创，每日更新`
- `关于 GateRank 评分、收费与排名独立性的声明`

独立声明保持可点击，并在新标签页打开现有完整声明页面。

## 视觉方案

采用已确认的方案 B：两条信息组成主标题上方的眉题区域。

- “行业首创，每日更新”使用紧凑玫红标签，承担品牌口号角色。
- 独立声明使用中性灰小号文字和近黑外链图标，视觉权重低于主标题。
- 主标题、说明文案、指标卡以及报告时间的内容与视觉主次保持不变。
- 桌面端两条信息同排展示；声明空间不足时允许收缩，但不得遮挡外链图标。
- hover 与键盘聚焦时声明文字变深、图标轻微右移，并保留清晰的 focus-visible 样式。

## 高度约束

首页 Hero 的外层纵向 padding 不增加。

- 桌面端利用右侧两张指标卡形成的现有内容高度余量容纳眉题，不增加 Hero 总高度。
- 移动端眉题分成两行完整展示；两张指标卡改为并排排列，报告时间独占下一行，以抵消眉题新增高度。
- 移动端不得通过截断隐藏独立声明标题，也不得产生横向溢出。

## 内容与交互

- 口号复用现有共享文案 `HOME_HERO_HIGHLIGHT_TEXT`，当前值为 `行业首创，每日更新`。
- 声明使用与排行页一致的完整标题 `关于 GateRank 评分、收费与排名独立性的声明`。
- 声明链接复用现有透明度声明 URL 构造逻辑；打开方式为新标签页，并使用 `noopener noreferrer`。
- 眉题仅提供声明链接，不新增按钮、接口、埋点或可配置字段。

## React 与 SSR

修改首页实际 React 组件 `src/pages/home/HomePageV3.tsx`，并同步修改 `backend/src/services/publicPageRenderer.ts` 的首页 SSR 标记与样式。

两套输出必须保持以下一致：

- 两条文案完全一致。
- 独立声明链接目标与新标签页语义一致。
- 视觉顺序均为口号、声明、主标题、说明文案。
- 桌面与移动端均遵守不增加 Hero 高度的布局策略。

## 验收标准

1. 桌面端 Hero 外层高度与修改前相同，两条新增信息完整可见。
2. 移动端声明不截断、不溢出，两个指标并排且报告时间仍清晰可读。
3. 声明点击后在新标签页打开完整声明页面。
4. 键盘可聚焦声明链接，并显示可见焦点状态。
5. React 与 SSR 均包含相同文案、链接和顺序。
6. 聚焦测试、TypeScript 检查与生产构建通过。

## 非目标

- 不修改完整独立声明页面内容。
- 不修改 Hero 主标题、说明文案、指标数据或报告时间逻辑。
- 不新增后台配置、API 或分析事件。
- 不调整 Hero 之外的首页区域。
