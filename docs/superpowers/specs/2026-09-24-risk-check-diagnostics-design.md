# 官网风险检测修复

用户已确认方案并授权实现；2026-09-25 追加生产发布授权。使用当前分支，按 GitHub 提交、对应镜像 CI 成功、生产部署和线上验收的顺序发布。

- 所有官网写入口共用 HTTP/HTTPS 地址规范化；无协议补 HTTPS，保留路径、查询和 fragment。历史读取保持兼容，探测时再规范化。
- 挑战页、访问受限、TLS-only 与网页正常分开。明确的 5xx 不能被 TLS 成功覆盖。网络失败与 5xx 最多复核一次，最多五次重定向，总预算 30 秒。
- 每次解析及跳转验证公网目标，连接固定到已检查的 IP，HTTP 不跟随库级自动跳转。诊断移除所有 query、fragment 和凭据。
- 独立保存每次诊断，与当天风险字段的写入使用同一事务；配置错误不覆盖指标。已有日指标只更新 domain_ok / ssl_days_left。
- 保留评分公式，历史数据不批量重写。后台展示最近检测、最近采用的结果时间、HTTP/TLS 分阶段记录。公开文案只陈述可达性。
- 回归测试包括规范化、Cloudflare、受限响应、5xx、根路径、重定向、公网校验、超时、事务回滚及配置错误保留旧指标。

验收：针对测试、前后端类型检查、完整后端测试、临时目录生产构建，以及本地浏览器桌面/窄屏诊断展示。生产验证需后续发布授权。
