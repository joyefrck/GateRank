# GateRank 首页广告位计费与投放设计

## 目标

在现有“优惠活动”投放体系中增加可选的首页广告位。普通优惠活动仍按现有广告月费计费；用户主动选择首页后，必须选择首页 1–4 号位，并按后台为该位置配置的独立月费计费。首页不是必选项，现有活动不自动迁移到首页。同时取消普通优惠活动的全局 6 条上限；首页仍只有四个固定且相互独占的位置。

## 已确认规则

- 新建优惠活动默认不投放首页。
- 未选择首页时，使用现有 `airport_ad_monthly_price` 计费。
- 选择首页时，必须选择 1、2、3、4 号位之一，并使用该位置的月费替代普通广告月费，不叠加收费。
- 首页每个位置同一时间只能存在一个有效投放。
- 已被有效活动占用的位置不能再次购买。
- 普通优惠活动不设全局数量上限，不再计算或展示“剩余 X/6”。
- 首页只展示明确购买了首页位置的有效优惠活动，严格按 1–4 号位排序。
- 首页空位保持为空，不用普通优惠活动补位。
- 现有活动全部兼容为“未投放首页”，不迁移、不补收费用。
- 编辑广告内容不收费，也不允许借编辑操作切换普通投放与首页位置。
- 续投沿用活动原有投放类型和首页位置，并按续投时后台当前配置的对应价格计费。
- 所有金额和位置可用性均由服务端重新计算与校验，客户端提交的价格不作为计费依据。

## 方案选择

### 采用：在现有优惠活动上增加可选首页位置

每条 `airport_ad_campaigns` 记录增加可空的首页位置字段。`null` 表示普通优惠活动，`1`–`4` 表示购买了对应首页位置。钱包扣费、活动内容、上下架、跑路状态、续投和交易记录继续复用现有流程。

这个方案保持一条活动只有一份内容和一个生命周期，不引入第二套订单或首页专用活动表，也不会改变现有优惠活动页的展示能力。

### 不采用：拆分首页广告订单

单独创建首页订单并关联优惠活动，能独立管理两个生命周期，但会引入订单同步、取消联动、续费拆分和双重状态管理，超出当前需求。

### 不采用：后台手工绑定首页位置

由管理员在后台把普通活动拖入首页位置实现简单，但无法满足用户购买时选择首页和位置、自动计费及位置占用校验的要求。

## 数据模型与兼容

### 营销计费配置

在现有 `marketing_billing` JSON 配置中增加：

```ts
home_ad_slot_monthly_prices: {
  1: number;
  2: number;
  3: number;
  4: number;
}
```

读取旧配置时，为缺失的四个位置价格使用当前普通广告月费作为兼容默认值。后台保存后写入四个明确价格。所有价格必须是大于或等于零、最多两位小数的有限数字。

### 优惠活动

在 `airport_ad_campaigns` 增加：

```sql
home_slot TINYINT UNSIGNED NULL
```

`NULL` 表示未购买首页位置；`1`–`4` 表示首页位置。迁移时旧记录保持 `NULL`。

不使用静态唯一索引判断位置占用，因为已过期和已取消记录可以复用同一位置。购买流程在数据库事务中锁定投放集合，并检查目标位置是否存在 `status = 'active'` 且 `ends_at > NOW()` 的活动。

## 公共数据契约

门户广告状态增加：

```ts
home_slot_monthly_prices: Record<1 | 2 | 3 | 4, number>;
home_slot_availability: Record<1 | 2 | 3 | 4, boolean>;
```

活动视图增加：

```ts
home_slot: 1 | 2 | 3 | 4 | null;
is_homepage: boolean;
```

新建活动请求增加：

```ts
is_homepage: boolean;
home_slot: 1 | 2 | 3 | 4 | null;
```

服务端规则为：

- `is_homepage = false` 时忽略并存储 `home_slot = null`。
- `is_homepage = true` 时 `home_slot` 必须为 1–4。
- 普通活动金额为普通月费乘月数。
- 首页活动金额为所选位置月费乘月数。
- 请求金额不进入服务端计费公式。

首页广告聚合数据保留活动真实字段并增加 `home_slot`。聚合服务只读取有效、已上架、未跑路且具有首页位置的活动。

门户广告状态不再返回或依赖 `remaining_slots` 和 `slot_limit`。购买接口不再统计全站有效活动数量，也不再返回 `AIRPORT_AD_SLOTS_SOLD_OUT`。首页位置可用性仍通过 `home_slot_availability` 表达。

## 后台管理

营销模块保留“广告投放月费（元）”，其文案明确为普通优惠活动月费。在同一区域增加“首页广告位月费（元）”配置卡，包含首页 1–4 号位四个独立输入框。

顶部费用摘要同时显示普通广告月费和首页四档价格。保存时四个位置价格与现有营销配置一起提交；失败时保留用户输入并展示现有错误反馈。

## 用户购买与续投

新建优惠活动表单增加“投放首页”选择，默认关闭。

- 关闭时不显示位置选择，价格摘要使用普通广告月费。
- 开启时显示 1–4 号位选择卡，卡片展示位置、月费和占用状态。
- 已占用位置禁用且明确显示“投放中”。
- 用户必须选中一个可用位置才能提交。
- 月数变化后，前端实时展示“对应月费 × 月数 = 本次费用”。
- 只有新建首页广告或编辑已有首页广告时，“活动标题”输入框下方才显示“显示在首页广告描述中。”
- 普通优惠活动的“活动标题”不显示该提示。

创建成功后，活动列表显示“普通优惠活动”或“首页 N 号位”。编辑内容时不提供位置变更。续投使用活动当前类型和位置，前端根据最新门户状态展示预计费用，服务端再次校验位置和余额。

如果活动因到期不再占用首页位置，其原记录仍保留 `home_slot` 作为历史信息；续投时只有目标位置当前可用或被该活动自身占用时才允许续投，否则返回明确的位置冲突错误。

## 首页展示

首页广告区固定包含四个位置槽位。渲染时用 `home_slot` 建立位置映射：

- 有有效活动的位置显示对应优惠活动卡片。
- 无活动的位置显示现有设计中的空态卡片，不移动其他位置补空。
- 数据顺序异常或重复时，以服务端校验结果为准；服务端只返回每个位置一个活动。
- 首页广告卡片的描述只读取 `discount_title`（表单中的“活动标题”），不再读取 `discount_description`。
- SPA 与 SSR 使用相同的首页广告描述规则。
- 普通优惠活动页继续使用 `discount_description`，不改变现有展示。

广告官网链接、报告链接、营销点击统计和 `rel="nofollow sponsored noopener noreferrer"` 继续沿用现有实现。

## 错误处理

- 非法位置：返回 400，并提示请选择首页 1–4 号位。
- 位置被占用：返回 409，并提示该首页位置已被占用，请选择其他位置。
- 余额不足：沿用现有余额不足响应，并使用服务端计算后的真实金额。
- 配置缺失：读取时使用普通广告月费兼容，保存后形成完整四档配置。
- 并发购买：事务锁内再次检查位置，只有一个请求能够成功。
- 不再存在普通优惠活动数量已满的错误；首页位置被占用时仍返回明确的位置冲突错误。

## 测试与验收

### 服务与仓储

- 旧营销配置能生成四档兼容价格。
- 后台能独立保存四个首页位置价格。
- 普通活动按普通月费计费且 `home_slot = null`。
- 有效活动数量超过 6 条时仍能购买普通优惠活动，且公共优惠活动列表不截断到 6 条。
- 首页活动按所选位置价格计费且不叠加普通月费。
- 非法位置、已占用位置和并发购买被拒绝。
- 取消或到期后位置重新可用。
- 续投按当前位置的最新价格计费。
- 现有活动读取为非首页活动。

### 路由与页面

- 门户状态返回四档价格和位置可用性。
- 用户购买表单默认不选择首页。
- 门户不展示“剩余 X/6”、满位警告，也不会因活动总数禁用新建。
- 选择首页后必须选择可用位置，费用随位置和月数更新。
- “显示在首页广告描述中。”只在首页广告表单状态出现。
- 活动列表正确显示普通投放或首页位置。
- 后台四个输入框可分别修改和保存。
- 首页只展示购买首页位置的活动，严格保持 1–4 号位，并用“活动标题”作为广告描述。
