# GateRank UI 风格 Skill 与优惠卡片操作区设计

## 目标

统一 GateRank 后续页面新增与视觉修改的设计语言，并把优惠卡片底部三个同权重按钮改造成符合首页风格的分层操作区。

## 优惠卡片操作区

采用已确认的方案 C：极简操作轨。

- “优惠详情”是唯一实体主操作，使用首页同款深色背景、白色文字、紧凑圆角、轻阴影和按压反馈。
- 主操作右侧显示方向箭头，悬浮时箭头轻微右移，强化进入详情的含义。
- “查看测评”和“官网”降级为无背景、无外框的文字操作，通过细分隔线形成节奏。
- “官网”保留外链图标、广告外链属性和点击统计。
- 桌面端三个操作同排；狭窄屏幕下主操作独占第一行，两个文字操作在第二行平分。
- 不改变路由、数据、复制按钮、曝光统计、SEO 或 SSR 内容。

## GateRank 项目 UI Skill

创建自动发现 skill：`~/.agents/skills/gaterank-ui-design`。

### 触发范围

当任务位于 GateRank 项目且涉及以下内容时触发：

- 新建公开页面、后台页面或组件。
- 修改页面布局、视觉层级、按钮、卡片、导航、响应式或交互状态。
- 根据截图、设计稿或现有页面统一 GateRank UI。
- 审查 GateRank 前端是否偏离首页风格。

### 内容结构

```text
gaterank-ui-design/
├── SKILL.md
├── agents/openai.yaml
└── references/gaterank-home-style.md
```

- `SKILL.md`：规定执行流程、首页基准、复用优先级、视觉原则、禁止项与验证门槛。
- `references/gaterank-home-style.md`：记录当前首页来源文件、视觉令牌、按钮层级、卡片与响应式范式。
- `agents/openai.yaml`：提供技能显示名称、简短说明和默认提示词。

不创建脚本和资产目录，因为本技能的核心是项目设计判断和现有组件复用，不需要确定性转换工具。

## 首页视觉基准

以 `src/pages/home/HomePageV3.tsx` 为首要 React 视觉来源，以 `backend/src/services/publicPageRenderer.ts` 的首页 SSR 样式为服务端基准。

- 颜色：白色和浅灰表面为主，`stone/slate` 深色承担主要操作，`indigo/blue` 用于语义强调。
- 层级：一个区域只保留一个高对比主操作，次操作使用白底细边框或文字链接。
- 形状：常规控件使用 8–12 像素圆角，主要卡片使用 18–24 像素圆角，不滥用胶囊。
- 质感：一像素浅边框、克制阴影、少量位移或缩放反馈，避免厚重装饰。
- 排版：标题黑体高权重，辅助信息保持灰阶和紧凑字距，操作文案短而明确。
- 响应式：桌面优先保持整齐节奏；移动端允许主操作独占一行，触控区域不小于 40 像素。

## 禁止项

- 三个或更多同样式、同权重的按钮并排或堆叠。
- 大面积无层级白框按钮组。
- 脱离首页系统的随意渐变、随机强调色或强阴影。
- 不必要的卡片嵌套、胶囊堆叠和纯装饰图标。
- 为视觉改动破坏现有链接、埋点、SSR/React 一致性或可访问性。

## 验证

- skill 使用官方初始化脚本创建，并通过 `quick_validate.py`。
- 优惠卡片源码测试覆盖深色主操作、文字次操作、响应式布局和原有外链属性。
- 运行前端类型检查与生产构建。
- 在真实浏览器验证桌面布局、移动端布局、主次层级和现有复制功能。
- 提交源代码和构建产物，工作区保持干净；不推送、不部署。
