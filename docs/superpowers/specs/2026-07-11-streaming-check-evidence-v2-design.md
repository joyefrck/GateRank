# 流媒体检测证据模型 v2 设计

## 目标

修复普通网页跨域限制造成的假阴性，让检测结果优先回答“当前出口地区是否在官方覆盖范围”，并把浏览器基础资源探测明确降级为补充证据。

## 结果模型

- `官方地区支持`：已识别国家，并且服务官方覆盖策略明确包含该国家。基础资源探测失败不能覆盖这个结论。
- `官方地区不支持`：已识别国家，并且完整的官方覆盖策略明确不包含该国家。基础资源可达不能覆盖这个结论。
- `基础资源可达`：服务缺少稳定的完整地区清单，但浏览器成功加载其公开静态资源。
- `浏览器限制`：静态资源加载失败或超时，可能来自 CORP、反机器人或网络限制；不得表述为服务无法连接。
- `待检测/检测中`：尚未产生本轮证据。

日本出口下，ChatGPT、Claude、Netflix、Disney+ 显示官方地区支持；TikTok 以基础资源结果为主；HBO Max 因日本未列入当前完整官方覆盖表而显示官方地区不支持。Netflix 仍只推断出口地区，完整片库必须通过手动片源复核。

## 数据与交互

共享注册表为每个平台分别保存官方打开地址和基础资源探测地址。用户每次点击仍触发一个同源地区判断请求和六个浏览器资源探测；页面加载时不请求，检测期间不可重复触发。

浏览器使用 `Image` 加载公开 favicon/CDN 资源。成功仅代表基础资源可达；失败统一解释为浏览器限制或探测超时。每个平台结果区提供“打开验证”入口，让用户在同一网络中完成账号、页面或播放层面的最终确认。

## SSR 与 SEO

SSR 首屏继续只显示待检测状态，不包含 IP。说明、FAQ 和结构化数据同步采用 v2 证据语义，避免搜索摘要继续宣称官网连通检测可以证明解锁。

## 测试

- 共享规则覆盖官方支持、官方不支持、地区未知、基础资源成功、失败和超时。
- 验证支持/不支持结论不再被浏览器探测覆盖。
- 验证日本的六个平台分类，特别是 HBO Max。
- 运行后端测试、前端类型检查、后端类型检查和构建。
- 在真实浏览器确认点击前无请求、点击后一次同源请求和六次资源探测、结果文案、外链与移动端布局。

## 边界

该网页不证明账号登录、订阅资格、完整片库或视频播放成功。服务端代请求不能代表用户出口，不纳入实现；更高精度检测需要浏览器扩展或本地客户端，属于后续独立项目。
