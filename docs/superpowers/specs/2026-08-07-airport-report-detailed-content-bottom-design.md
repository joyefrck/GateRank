# 机场报告详细正文置底设计

## 背景与目标

当前 `/airports/:slug` 报告页在 Hero 后立即展示“测评摘要”。该区块先重复总分、状态、风险惩罚、可用率和延迟等页面已有指标，再把八段实际解读放进默认关闭的 `<details>`。用户需要主动逐项展开，容易把真实正文误认为占位或缺失内容，也打断了从概览、能力、评分、指标、趋势到结论的主要阅读顺序。

本次把该区块改为页面最底部的“详细测评数据”：取消折叠，完整展示由当前报告视图生成的真实数据和解释。React 与服务端 HTML 必须具有相同内容、语义和顺序。

## 已确认方案

采用单一白色报告容器与分隔线组织正文，不再渲染八个相同的灰色折叠框。

- 标题改为 `{机场名} 详细测评数据`。
- 删除当前重复指标的顶部摘要框，不再显示“详细解读已折叠保留”。
- 每个主题使用语义化 `<article>`、`<h3>`、正文说明和数据定义列表。
- 全部主题默认可见，不使用 `<details>` 或需要点击的展开控件。
- 整个区块移动到页面最底部。
- 区块末尾继续保留可抓取的相关机场对比链接。

视觉原则是克制、数据优先：白色背景、浅灰分隔线、近黑标题、灰色说明文字和少量蓝色语义强调。桌面端数据项可以两列排列，移动端回落为单列；正文不使用密集胶囊标签堆叠。

## 页面顺序与导航

React 报告页顺序调整为：

1. 概览 Hero
2. 数据快照
3. 服务能力
4. 客户端下载入口
5. 评分拆解
6. 核心指标
7. 趋势
8. 套餐与 Telegram
9. 结论与建议
10. 详细测评数据

服务端 HTML 保持现有报告内容和 FAQ，在所有现有区块之后输出“详细测评数据”，使它同样成为服务端页面最后一个正文区块。

`shared/reportUi.ts` 中的 `REPORT_ANCHOR_SECTIONS` 同步把 `report-content` 移到数组末尾，标签由“测评摘要”改为“详细测评”。这样固定导航、滚动激活逻辑和页面真实顺序一致；滚动到文档底部时，最后激活项应为“详细测评”。

## 共享数据模型

`shared/publicSeo.ts` 继续作为详细正文的唯一数据生成入口。把现有纯字符串 `facts` 改成结构化数据项：

```ts
export interface PublicReportContentFact {
  label: string;
  value: string;
  href?: string;
}

export interface PublicReportContentSection {
  title: string;
  body: string;
  facts: PublicReportContentFact[];
}
```

结构化数据项让 SSR 和 React 能用相同的标签、值和可选链接渲染 `<dl>`，避免在渲染层拆解字符串。Telegram 群或频道 URL 可以作为经过现有外链规范化与转义处理的链接输出；普通数据只渲染文本。

不新增数据库字段、接口或后台配置。所有内容都来自现有 `PublicReportSeoView` / `ReportView`：

- `date`
- `airport.status`
- `summary_card.score`、`summary_card.conclusion`
- `ranking`
- `score_breakdown`
- `metrics`
- `trends`
- `capabilities.plan`
- `capabilities.payment_methods`
- `capabilities.regions`
- `capabilities.clients`
- `capabilities.import_methods`
- `capabilities.streaming`
- `capabilities.telegram`

## 详细正文内容

### 综合结论

展示报告日期、公开总分、当前状态、综合评级、当前结论和五类榜单的真实名次。未进入某个榜单时显示“未上榜”，不能省略为看似没有该维度。

### 风险解读

展示风险维度得分、总风险惩罚、官网探测扣分、SSL 扣分、投诉扣分、历史异常扣分、近期投诉数量和历史异常次数。正文明确这些是当前监测结果，不是未来无风险保证。

### 稳定性与性能

展示 30 天可用率、稳定天数、健康天数、稳定性评级、中位延迟、下载速率、代理请求失败率，以及评分、可用率、延迟和下载趋势的首尾变化。趋势样本不足时继续使用现有“暂无足够趋势样本”口径。

### 套餐、价格与支付

展示月付、季付、半年付、年付、试用、不限时套餐的三态结果，最低月付价格、最低年付折算月价，以及全部已收录支付方式。

布尔值为 `true` 时显示“支持”，为 `false` 时显示“不支持”，为 `null` 或缺失时显示“未收录”。价格缺失显示“未收录”，不得输出 `¥0`。

### 节点、客户端与解锁

展示全部已收录节点地区，不再只在正文中截取前五个地区。每个地区保留节点数量、线路类型、原生 IP 和家宽信息；同时展示地区总数与节点总数。客户端、导入方式和解锁能力展示全部已收录项，不使用“前六项 + 等 N 项”的摘要写法。

节点数量为零时只表示当前未记录到正数节点，不把零推断为该地区不可用。空数组统一显示“未收录”。

### Telegram 与售后

展示 Telegram 群、群链接、频道、频道链接、群内发言、客服 Bot、工单系统、群人数和最近活跃时间。链接缺失显示“未收录”；成员数量和活跃时间缺失不能改写为“不支持”。

### 适合哪些用户

基于当前稳定性、延迟、下载速度、代理请求失败率、客户端和解锁能力生成适用场景说明，并展示用于判断的原始数据。样本不足 30 天时明确提醒长期可靠性仍需继续观察。

### 选择前要注意什么

保留风险提示，同时列出当前状态、数据日期、投诉、历史异常、试用、支付方式和趋势样本天数。GateRank 分数继续被描述为辅助决策依据，不构成购买或长期可靠性保证。

## 缺失数据与真实性规则

- 所有数字直接格式化现有视图字段，不编造、平滑或补全。
- `null`、`undefined` 和空集合使用“未收录”。
- “未收录”不能改写为“不支持”“没有”或“不可用”。
- `false` 可以显示“不支持”，因为它是明确记录的三态值。
- 分数隐藏时显示“暂不公开”，不能退回 `0`。
- 外部 URL 继续经过协议规范化、HTML 属性转义，并使用 `nofollow noreferrer noopener`。
- 报告日期和回退提示保持现有行为，不把生成时间冒充为数据更新时间。

## SSR 与 React 渲染

### React

`ReportContentNarrative` 调整为详细正文组件并移动到 `ReportContentV2` 最后一项。移除 summary 卡和 `<details>`，使用共享 section 数据渲染正文与 `<dl>`。

### SSR

`renderReportContentSections()` 使用相同 section 数据输出 `<article>` 与 `<dl>`，并从 Hero 后移到 `renderReportFaq()` 之后。删除旧 summary 和 details 样式，新增详细正文分隔与响应式数据项样式。

两侧都不得复制数据拼接逻辑；文字、标签、值和链接由共享 helper 提供。

## 可访问性与响应式

- 主题标题使用真实 `<h3>`，不再依赖 `<summary>` 的浏览器交互语义。
- 数据使用 `<dl>`、`<dt>`、`<dd>`，标签和值关系明确。
- 外链保持键盘可聚焦和可见 focus 样式。
- 320px 宽度下正文、长 URL 和长客户端名称不得横向溢出。
- 桌面端数据列表允许两列；移动端单列并保留至少 40px 的链接触控区域。

## 测试与验收

### 共享内容

- 八个主题均从 fixture 的真实字段生成精确值。
- 综合结论包含真实榜单名次和“未上榜”。
- 节点正文包含全部地区、地区总数和节点总数。
- 客户端、导入方式、支付和解锁能力不截断。
- Telegram 链接以结构化 `href` 返回。
- 缺失价格、链接、列表和三态字段时使用正确口径，不出现 `undefined`、`null`、`NaN` 或虚假 `¥0`。

### SSR

- 原始 HTML 中 `report-content` 位于 FAQ 和其他报告区块之后。
- 不再包含 `<details class="report-content-detail">`、旧 summary 卡或“详细解读已折叠保留”。
- 包含语义化 `<article>`、`<h3>`、`<dl>`、`<dt>` 和 `<dd>`。
- 所有真实 fixture 数据可在原始 HTML 中检索。

### React 与导航

- `ReportContentV2` 把详细正文组件放在 `ReportConclusion` 之后。
- `REPORT_ANCHOR_SECTIONS` 的最后一项是 `report-content`，标签为“详细测评”。
- 页面末尾时激活导航仍解析为最后一项。
- SSR 与 React 的主题顺序和标签一致。

### 完整验证

- 聚焦后端路由测试通过。
- `shared/reportUi` 导航测试通过。
- 服务端 TypeScript 检查通过。
- 前端 TypeScript 检查通过。
- 生产构建通过并更新仓库跟踪的 bundle。
- 使用真实浏览器检查桌面端和移动端：详细正文位于底部、默认全部可见、无横向溢出，固定导航顺序正确。

## 非目标

- 不修改 GateRank 评分、趋势、风险或排名算法。
- 不新增或回填数据库数据。
- 不改动 Hero、评分卡、能力卡、趋势图、套餐/Telegram 主区块或 FAQ 文案。
- 不新增单机场人工正文编辑器。
- 不把缺失数据推断成明确支持或不支持。
- 不改变广告、外链计费或营销统计逻辑。
