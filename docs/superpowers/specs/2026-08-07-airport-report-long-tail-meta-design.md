# 机场报告长尾词元信息增强设计

## 背景与目标

GateRank 的 `/airports/:slug` 详情页已经通过服务端 HTML 和 React 页面展示机场评分、价格、支付方式、套餐、节点、Telegram、客户端、稳定性与风险信息。本次只增强每个机场详情页的 SEO 元信息，让搜索结果摘要更直接覆盖以下长尾意图：

- `{机场名}价格多少`
- `{机场名}套餐价格`
- `{机场名}支持USDT吗`
- `{机场名}有哪些节点`
- `{机场名}电报群` / `{机场名}Telegram群`
- `{机场名}是否值得使用` / `{机场名}是否支持使用`
- `{机场名}支持哪些客户端`

所有公开机场使用同一套动态生成逻辑，不为大象网络或其他单个机场维护人工特例。

## 核心方案

只修改 `shared/publicSeo.ts` 中机场详情页的 `description` 与 `keywords` 生成逻辑。以下内容保持不变：

- `<title>` 与页面 H1。
- 页面正文、图文区块、卡片、FAQ 和交互。
- `FAQPage`、`Product`、`Review` 等 JSON-LD。
- canonical、robots、OG 图片和路由。
- 报告数据接口与数据库结构。

共享 SEO helper 继续同时服务后端 SSR 和 React 接管，保证初始 HTML 与浏览器运行后的元信息一致。

## Description 生成规则

Description 以用户问题开场，然后用当前报告已经收录的事实回答搜索意图。大象网络的目标形态如下：

```text
大象网络价格多少、支持 USDT 吗、有哪些套餐和节点、是否有电报群、支持哪些客户端？GateRank 汇总最低月付 ¥12、支付方式、节点地区、客户端、当前评分与稳定性数据，帮助判断大象网络是否值得使用。
```

具体规则：

1. 开头包含机场名称以及价格、USDT、套餐、节点、Telegram 和客户端搜索意图。
2. 最低月付价格存在时输出真实价格；缺失时使用“价格信息”概括，不输出 `¥0` 或推测价格。
3. 支付方式、节点和客户端用类别概括承接现有正文，不在 description 中塞入过长清单。
4. 保留当前分数、状态或稳定性中的核心判断信息，让摘要仍具有报告属性，而不是变成纯关键词列表。
5. 结尾自然包含“是否值得使用”。
6. Description 总长度保持在现有测试约束的 80–180 个字符内。
7. HTML 输出继续通过现有转义逻辑处理机场名称和动态值。

数据未收录不等同于不支持。Description 不得因为支付方式列表中没有 USDT 就断言该机场“不支持 USDT”，也不得根据缺失的节点、Telegram 或客户端数据生成否定结论。

## Keywords 生成规则

在现有“怎么样、测评、跑路、官网”等关键词基础上，为每个机场动态追加：

```text
{机场名}价格多少
{机场名}套餐价格
{机场名}支持USDT吗
{机场名}有哪些节点
{机场名}电报群
{机场名}Telegram群
{机场名}是否值得使用
{机场名}是否支持使用
{机场名}支持哪些客户端
```

关键词使用逗号分隔并去除重复项。保留通用关键词 `机场榜GateRank`、`机场测评报告`、`机场评分`、`机场趋势`、`机场榜`、`机场推荐`、`机场官网`、`跑路风险` 和 `GateRank`。

`meta keywords` 不作为 Google 排名保证；保留它是为了补齐页面元信息和兼容其他检索系统。本次可预期的主要改进是搜索摘要与长尾意图更匹配，而不是仅靠 keywords 获得排名。

## SSR 与 React 一致性

`buildReportSeo()` 是唯一生成入口：

- `backend/src/services/publicPageRenderer.ts` 使用它输出原始 HTML meta 标签。
- `src/App.tsx` 使用它更新 React 接管后的文档元信息。

不得在后端 renderer 或 React 页面中复制第二套长尾词模板。修改共享 helper 后，两侧自然获得相同结果。

## 测试与验收

在现有机场详情页路由测试中增加以下断言：

1. SSR 原始 HTML 的 `meta keywords` 包含全部新增机场专属长尾词。
2. Description 包含机场名称、价格、USDT、套餐、节点、电报群、客户端和“是否值得使用”意图。
3. 有最低月付价格时，Description 包含真实价格。
4. Description 长度继续保持 80–180 个字符。
5. 现有 title、H1、canonical、FAQ 和结构化数据断言继续通过，证明页面内容与技术 SEO 未被意外改动。
6. 缺少可选能力数据的视图仍可生成合法元信息，不出现 `undefined`、`null`、`NaN`、虚假价格或错误的否定结论。

完成聚焦测试后运行服务端类型检查和生产构建。构建产物如由仓库跟踪，仅包含本次共享 SEO 逻辑带来的正常更新。

## 非目标

- 不新增详情页内容区块或长尾落地子页面。
- 不修改现有 FAQ 问题和答案。
- 不把所有关键词塞入 title 或 H1。
- 不新增后台 SEO 编辑字段。
- 不为单个机场添加硬编码文案。
- 不承诺 Google 固定采用 description、立即收录或达到指定排名。
