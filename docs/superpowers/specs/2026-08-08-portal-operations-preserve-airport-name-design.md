# 申请人运营资料同步保留正式机场名称

## 目标

申请人后台保存运营资料时，不允许写入正式机场记录的 `name` 字段。管理员在机场管理后台设置的名称始终保留。

## 范围

- 保留 `airport_applications.name` 的现有值和现有只读行为。
- `PATCH /portal/application/operations` 仍同步官网、价格、试用、流媒体、支付、Telegram、成立日期、介绍、测试账号、测试密码、资料档案及按现有条件提交的订阅地址。
- `syncApprovedAirportOperations()` 构造正式机场更新补丁时不包含 `name`。
- 不修改管理员改名接口，不增加申请表名称联动，不改变申请人后台界面。

## 数据流

申请人提交运营资料后，服务端可继续使用申请表名称维护申请记录，但传给 `airportRepository.update()` 的正式机场补丁必须省略 `name`。因此即使申请表仍保存旧名称，也不会覆盖管理员已更新的 `airports.name`。

## 回归验证

调整现有门户路由测试，使申请表名称与正式机场名称不同，并断言：

1. 运营资料保存成功；
2. 正式机场更新补丁没有 `name` 属性；
3. 正式机场的新名称保持不变；
4. 其他运营资料仍正常同步。

运行门户路由针对性测试以及后端类型检查。
