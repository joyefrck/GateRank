# GateRank 首页观察时长入驻口径设计

## 背景与根因

首页排行榜当前使用 `founded_on` 计算“观察时长”。该字段表示机场自身的成立日期，不代表 GateRank 开始观察该机场的时间，因此会把成立已久、近期才入驻的机场显示成数百天观察。

生产接口已经同时返回 `airports.created_at`。该字段在机场通过申请或由后台录入时生成，代表机场进入 GateRank 的时间，符合“观察时长从入驻开始统计”的产品口径。

## 已确认方案

- 首页所有“观察时长”统一以 `airports.created_at` 为起点。
- 入驻当天计为第 1 天，与现有新入榜标签和首页新入榜卡片口径保持一致。
- `founded_on` 只表示机场成立日期，不再参与首页观察时长计算。
- 目标日期早于入驻日期时显示 0 天；日期缺失或无效时显示现有占位符，不伪造时长。

## 数据流与修改范围

### 首页排行榜

- 公共排行榜接口继续返回已有的 `created_at`，不新增数据库字段或接口请求。
- React 桌面表格和移动卡片改用 `item.created_at`。
- SSR 首页排行榜改用 `item.created_at`，确保首屏 HTML 与客户端渲染一致。

### 首页广告卡片

- 广告查询补充机场记录的 `created_at`，并与广告活动自身的 `created_at` 分开命名。
- `tracking_days` 改为根据机场入驻时间计算；活动创建时间、广告开始时间和机场成立日期都不作为观察起点。
- 即使首页卡片上下文缺失，也使用查询结果中的机场入驻时间，避免回退到错误口径。

## 不在范围内

- 不修改机场成立日期、入驻日期或任何生产历史数据。
- 不修改评分、排序、标签阈值、报告观察样本或广告活动统计起点。
- 不修改全量排行榜中与“观察时长”无关的展示。

## 验证

- 增加回归用例，使 `founded_on` 与 `created_at` 明显不同，确认 React 和 SSR 只使用 `created_at`。
- 验证入驻当天显示 1 天，未来入驻日期显示 0 天，无效日期使用占位符。
- 验证首页广告卡片的 `tracking_days` 使用机场入驻时间。
- 运行聚焦后端测试、前后端类型检查、完整后端测试和生产构建。
