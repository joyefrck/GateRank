# SSR 链接颜色级联修复设计

## 背景

生产首页由后端 SSR 输出完整 HTML，并同时加载 Vite 生成的 Tailwind 样式和 `publicPageRenderer.ts` 中的内联公共页样式。排行榜“查看报告”链接包含 `text-white`，但内联公共页样式中的未分层规则 `a { color: inherit; }` 优先于 Tailwind `@layer utilities`，导致链接继承表格正文的深色文字。

测试环境通常直接使用 Vite 页面外壳，不注入这段 SSR 样式，因此按钮文字正常显示为白色。

## 目标

- 生产 SSR 页面中的排行榜黑色按钮显示白色文字。
- Tailwind 链接文字工具类在 SSR 页面中按预期生效。
- 未显式设置文字颜色的 SSR 链接继续继承父元素颜色。
- 不改变排行榜数据、导航、按钮尺寸、背景色、交互或目标地址。

## 方案比较

### 方案一：将通用链接色放入 `@layer base`（采用）

把 `a { color: inherit; }` 改为 `@layer base { a { color: inherit; } }`。默认继承行为保留，同时 Tailwind `utilities` 层的 `text-white`、`text-indigo-*` 等工具类可以覆盖基础规则。

这是最接近当前样式意图的修复，影响面可控，也符合 Tailwind 的级联层模型。

### 方案二：给排行榜按钮增加专用高优先级规则

可为按钮增加专用类，并使用未分层 CSS 或 `!important` 强制白色。该方案只遮住当前按钮症状，其他 SSR 链接仍可能遇到相同冲突，因此不采用。

### 方案三：删除通用 `a { color: inherit; }`

可以恢复工具类颜色，但未显式设置颜色的 SSR 链接可能回退为浏览器默认蓝色，公共页视觉回归风险更高，因此不采用。

## 修改范围

- 修改 `backend/src/services/publicPageRenderer.ts` 中公共页内联样式的链接基础规则。
- 在现有公共页渲染测试中增加回归断言，要求规则位于 `@layer base`，并禁止重新出现未分层的全局链接色规则。
- 不修改 `HomePageV3.tsx` 按钮类名；其中的 `text-white` 已经正确表达组件意图。
- 不修改或手工编辑 `dist`；前端源代码没有变化，构建只用于验证。

## 验证

1. 先运行新增回归测试，确认它在当前代码上失败。
2. 实施一处 CSS 层级修改后，确认聚焦测试通过。
3. 运行相关公共页测试、TypeScript 检查和生产构建。
4. 在 SSR 页面中检查排行榜第一个“查看报告”链接的 computed style：背景保持深色，`color` 为白色。
5. 检查普通 SSR 链接仍继承父元素颜色，导航和公共页无明显样式回归。

## 发布边界

代码和验证完成后不自动部署。生产发布需在用户明确授权后执行，并保持 Web/API 镜像版本一致；发布后再以生产 DOM computed style 和截图作为最终验收证据。
