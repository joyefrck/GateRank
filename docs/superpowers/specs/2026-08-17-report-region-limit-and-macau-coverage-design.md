# 报告地区展示上限与澳门网络覆盖识别设计

## 目标

- 报告详情页“节点覆盖”最多展示 14 个地区，超过 14 个时继续显示剩余数量。
- 网络覆盖采集将澳门节点识别为 `MO / 澳门 / extended`，不再归入 `UNKNOWN`。
- React 页面与服务端 SSR 保持一致，不改变现有卡片结构、排序和视觉样式。

## 方案

### 报告详情页

在 React `ReportRegionGroup` 与 SSR `renderRegionGroup` 中使用同一个明确的展示上限 14。地区仍按现有数据顺序展示；总数超过 14 时，脚注显示“另有 N 个地区”。

视觉原则：保留当前五列服务能力卡片体系，只增加“节点覆盖”卡片的信息密度，不新增控件、交互或视觉层级。

### 澳门识别

在网络覆盖地区定义中新增扩展地区：

- 代码：`MO`
- 名称：`澳门`
- 别名：`mo`、`macau`、`macao`、`澳门`、`澳門`、`🇲🇴`

短代码 `mo` 继续使用现有字母数字边界匹配，避免命中其他英文单词；中文别名不包含“澳”单字，因此不会误识别“澳大利亚”或“澳洲”。澳门计入扩展地区覆盖分，其余评分公式和权重不变。

## 数据流与兼容性

报告展示上限只影响 React/SSR 输出，不修改 API 数据。澳门分类在新的网络覆盖运行计算并持久化时生效；历史已保存的运行结果不回写。

## 验证

- 新增网络覆盖分类测试，覆盖简体、繁体、英文、代码和旗帜形式，并验证澳大利亚仍为 `AU`。
- 新增 React 源码契约与 SSR 渲染测试，验证前 14 个地区可见、第 15 个隐藏且脚注为“另有 1 个地区”。
- 运行聚焦测试、完整后端测试、前后端类型检查、lint、生产构建和 `git diff --check`。
- 在本地真实浏览器检查桌面和移动端报告详情页布局。
