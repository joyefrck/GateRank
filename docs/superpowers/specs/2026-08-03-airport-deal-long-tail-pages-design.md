# 单机场优惠长尾页设计

## 背景与目标

当前 `/deals` 是机场优惠聚合页，服务端原始 HTML 已包含活动机场、优惠码和 `Offer` 数据，但页面的 title、H1、description 与 canonical 都面向“机场优惠码大全”这一通用搜索意图。它无法为“大象网络优惠码”“大象网络优惠”“大象网络折扣”等单机场长尾词提供独立且稳定的落地页。

本设计为每个公开机场自动提供一个永久优惠详情 URL，专门承接单机场优惠类搜索意图。页面由现有机场资料和广告活动数据动态生成，不要求管理员逐页创建内容。Google 的抓取和收录不承诺即时发生；系统目标是让新 URL 上线后立即具备可抓取、可索引、可持续更新的完整条件。

## 核心决策

### 一个机场只对应一个优惠页面

优惠详情页的唯一身份是 `airport_slug`，不是 `campaign_id`：

```text
/deals/:airport_slug
```

例如，大象网络始终使用：

```text
/deals/elphantroute
```

同一个机场同时存在一个或多个有效活动时，所有活动汇总到这个页面中，以独立优惠卡展示。创建、编辑、续费或取消活动都只改变页面内容，不创建新的 URL，也不改变 canonical。系统不得生成 `/deals/:campaign_id`、带活动 ID 的详情页或其他可索引重复页。

### 页面永久存在

每个拥有公开机场测评页的机场都自动拥有优惠页：

- 有有效活动时展示全部有效活动。
- 没有有效活动时返回 `200`，明确显示“当前暂无有效优惠码”，并继续展示机场价格、试用、支付、状态、测评入口和优惠使用说明。
- 机场存在风险状态时，风险提示优先于优惠内容展示。
- 只有 slug 不对应任何公开机场时才返回 `404`。
- 活动过期不删除页面、不修改 URL，也不把页面临时设为 `noindex`。

这一策略保持 URL 和已积累的搜索信号稳定。无活动页面必须包含真实的机场专属信息，不能只批量输出一句占位文案。

## 方案选择

采用独立动态页，而不采用以下替代方案：

1. 不把优惠主内容直接塞入 `/airports/:slug`。测评页继续承接“怎么样、测评、稳定性、跑路风险”等意图，优惠页承接“优惠码、优惠、折扣”等意图，减少关键词和页面职责冲突。
2. 不为每个活动生成 News 文章。活动文章容易过期和重复，无法保证一个机场只有一个稳定的优惠入口。
3. 不使用查询参数作为可索引入口。`/deals?airport=...` 适合筛选但不适合作为稳定、清晰的单机场 canonical。

## 页面信息架构

以大象网络为例，页面使用以下动态 SEO 文案模式：

```text
Title: 大象网络优惠码 2026｜最新优惠、折扣活动与使用说明 | 机场榜GateRank
H1: 大象网络优惠码与最新优惠活动
Description: 查询大象网络最新优惠码、折扣说明、适用套餐、活动期限、叠加与退款规则。当前暂无优惠时也会明确提示，并提供价格、试用和测评信息。
Canonical: https://gate-rank.com/deals/elphantroute
```

年份从当前业务时区动态生成。页面正文按以下顺序组织：

1. 面包屑：首页、活动优惠、当前机场。
2. 机场优惠状态区：机场名称、当前有效活动数量和最近核对时间。
3. 风险提醒：当机场处于跑路、风险观察或其他异常状态时置顶显示。
4. 当前优惠区：按活动结束时间升序展示该机场的全部有效活动，每张卡包含优惠码、折扣标题、折扣说明、适用套餐、开始和结束时间、是否可叠加、退款规则。
5. 无优惠状态：明确说明当前未发现有效活动，不展示过期优惠码，不暗示不存在的折扣。
6. 机场参考信息：月付价格、是否试用、支付方式、公开状态以及测评报告入口；只展示已有数据。
7. 使用与判断说明：如何使用优惠码、如何核对活动有效期、优惠与 GateRank Score 相互独立。
8. 机场专属 FAQ：围绕当前是否有优惠、优惠是否影响排名、过期处理和购买前需要核对的条件生成可见问答。
9. 相关入口：返回优惠大全、查看该机场测评、访问机场官网。

官网属于广告或商业外链，使用 `rel="sponsored nofollow noreferrer noopener"`。页面不得根据缺失字段编造折后价、原价、退款期限或优惠力度。

## 数据模型与汇总规则

页面视图以机场为根对象，建议定义独立的 `AirportDealDetailView`：

```text
airport: 公开机场摘要
active_deals: AirportDealView[]
generated_at: 当前视图生成时间
```

路由先按 slug 读取公开机场，再读取全部当前有效活动，最后按 `airport_id` 过滤并汇总。汇总约束如下：

- 一个 `airport_id` / `airport_slug` 只生成一个详情视图。
- 多个活动保留各自的 `campaign_id` 作为卡片、曝光和点击统计身份，但不能参与页面 URL 或 canonical 生成。
- 有效活动沿用现有条件：状态为 active、开始时间不晚于当前时间、结束时间晚于当前时间、机场仍公开可见。
- 页面活动排序固定为结束时间升序、开始时间升序、活动 ID 升序，保证 SSR 与 React 输出一致。
- 同一机场的重复活动不合并字段；每个真实活动展示一张卡，但页面级 SEO 和结构化数据只对应同一个机场 URL。

## 路由与渲染

后端增加：

```text
GET /deals/:slug
GET /api/v1/pages/deals/:slug
```

HTML 路由负责服务端完整渲染，API 路由为 React 客户端导航和无初始数据时的回退提供同一份视图。`/deals/:slug` 的原始响应必须直接包含机场名称、H1、优惠状态、活动详情、canonical 和 JSON-LD，不能依赖浏览器执行 JavaScript 后才补齐。

前端增加相同路径的路由识别和详情组件。SSR 初始数据增加独立 kind，React 接管时复用该数据，不重复请求，也不能改变 title、canonical、活动排序或可见内容。

现有 `/deals` 保持聚合页职责。它的每张机场优惠卡把机场名称和“查看优惠详情”链接到 `/deals/:airport_slug`；复制优惠码、查看测评和访问官网能力继续保留。同一机场在聚合页有多个活动时可以展示多张活动卡，但它们全部链接到同一个机场优惠页。

机场测评页增加一个指向 `/deals/:airport_slug` 的可抓取文本链接。即使当前没有活动，该链接也使用“查看该机场优惠信息”一类不误导的文案。

## SEO 与结构化数据

每个单机场优惠页提供：

- 自引用 canonical。
- `index,follow,max-image-preview:large`。
- 机场名与“优惠码、优惠、折扣”自然组合的 title、H1 和 description。
- `BreadcrumbList`。
- 表达当前页面和机场关系的 `WebPage` / `Service` 数据。
- 有有效活动时，输出与页面可见内容一致的 `Offer` 数据；多个活动对应多个 Offer，但共同属于当前机场服务和当前页面。
- 可见 FAQ 对应的 `FAQPage` 数据。

不为了富结果补造 `price` 或 `priceCurrency`。结构化数据帮助搜索引擎理解页面，但不承诺 Google 展示富结果。

`/sitemap.xml` 自动加入所有公开机场的 `/deals/:slug`，而不是按活动生成 URL。`lastmod` 使用机场资料或相关优惠活动的真实最近更新时间；只有真实内容变化时才更新。活动新增、编辑、续费、取消和过期只更新同一个 sitemap 项。

Google Search Console 只需提交更新后的 sitemap。上线首批可对 `/deals/elphantroute` 等重点页面使用 URL Inspection 请求编入索引，其余页面依靠 sitemap 和站内链接发现。普通优惠页面不使用 Google Indexing API 批量推送。

## 缓存与更新时效

详情 HTML、详情 API 和 sitemap 使用一致的数据边界。活动变更后不得出现聚合页已更新而详情页仍长期保留旧优惠的状态。沿用现有公共页缓存时，允许最多五分钟的缓存可见延迟；缓存键按 slug 隔离：

```text
deal-detail:<airport_slug>
```

页面中的“最近核对时间”表示服务端视图生成时间，不冒充机场官方更新时间或 Google 抓取时间。

## 异常处理

- 未知 slug：返回真正的 `404` HTML，不输出可索引 canonical。
- 机场存在但活动查询失败：返回 `500`，不能把查询故障误展示为“暂无优惠”。
- 机场存在且活动数组为空：正常返回 `200` 和无优惠内容。
- 单个活动缺少必需展示字段：后端数据校验失败并记录错误，不生成误导性卡片。
- 外部官网地址无效：不渲染可点击官网按钮，但页面和测评入口仍可使用。

## 测试与验收

### 路由和汇总

- 已公开机场无活动时返回 `200`。
- 一个机场一个活动时返回一个详情页和一张活动卡。
- 一个机场两个活动时仍只有 `/deals/:slug` 一个 canonical，页面包含两张活动卡。
- 两个机场分别生成两个不同 slug 页面。
- 未知 slug 返回 `404`。
- 活动过期后页面继续返回 `200`，且不再显示过期优惠码。

### SSR 与前端一致性

- 原始 HTML 包含动态 title、H1、description、canonical、机场名和所有有效活动。
- SSR 初始数据和详情 API 具有相同结构与排序。
- React 接管后不重复请求、不删除内容、不修改 canonical。
- 聚合页的同机场多张活动卡全部链接到同一个优惠详情 URL。

### SEO

- sitemap 对每个公开机场只包含一个 `/deals/:slug`。
- sitemap 不包含 campaign ID、查询参数或重复 canonical。
- 结构化数据与可见内容一致并可被解析。
- 页面之间存在 `/deals`、优惠详情页和机场测评页的双向可抓取链接。
- 无活动页面包含真实机场专属数据，不是只有机场名不同的薄模板。

### 重点上线验证

```text
GET /deals/elphantroute -> 200
canonical -> https://gate-rank.com/deals/elphantroute
H1 -> 大象网络优惠码与最新优惠活动
sitemap -> /deals/elphantroute 仅出现一次
```

如大象网络同时存在两个有效活动，原始 HTML 必须同时包含两个活动，但 title、H1、canonical 和 sitemap 项仍只有一套。

## 不在本次范围

- 不承诺 Google 立即抓取、立即收录或固定排名。
- 不新增站内搜索框。
- 不创建按 campaign ID、年份、月份或优惠码拆分的索引页。
- 不自动生成 News 优惠文章。
- 不改变 GateRank Score、榜单排序或广告计费规则。
