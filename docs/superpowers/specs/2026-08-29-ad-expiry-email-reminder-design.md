# 广告到期邮件提醒设计

## 目标

为仍在投放的广告增加到期前邮件提醒：按北京时间在到期前第 3、2、1 天的上午 09:00 各执行一次；同一申请人的多条临期广告合并为一封邮件，并明确展示每条广告剩余天数、申请人后台地址和续费操作指引。到期当天不发送。

## 方案选择

采用 GateRank 现有后台调度系统中的独立任务 `ad_expiry_reminder`。不复用凌晨执行的余额展示同步任务，避免改变余额业务时效或让两类任务互相影响；也不使用服务器 Cron，以保留后台开关、执行时间、手动重跑和运行记录能力。

## 触发规则

- 调度任务默认执行时间为 `09:00`，时区固定为 `Asia/Shanghai`。
- 以调度运行日期为基准，只选择广告状态为 `active`、且 `ends_at` 的北京时间日期分别为运行日期后第 1、2、3 天的记录。
- 到期当天、已到期广告和已取消广告不进入提醒。
- 剩余天数按北京时间自然日计算，邮件中每条广告分别展示 `1 天`、`2 天` 或 `3 天`。
- 同一申请人账号的所有命中广告合并发送；收件地址使用该申请人后台账号邮箱。

## 数据与服务边界

### 临期广告查询

由广告仓储提供面向提醒场景的查询，返回广告 ID、机场名称、广告位置、到期时间、申请人账号 ID 和账号邮箱。查询只负责筛选与返回规范数据，不负责发信。

### 发送去重

新增广告到期提醒发送记录表，以 `申请人账号 ID + 提醒日期` 为唯一约束，保存发送状态、尝试次数、失败原因和成功时间。

- 当天首次执行可发送。
- 已成功记录在当天手动重跑、服务重启或重复调度时直接跳过。
- 失败记录允许当天重试；成功收件人不会因其他收件人失败而重发。
- SMTP 成功后写入成功状态；失败时保存经过截断和清理的错误摘要，不记录邮件正文或敏感配置。

### 提醒服务

独立提醒服务负责按申请人分组、检查发送记录、调用邮件服务并形成结构化汇总：候选广告数、申请人数、成功数、失败数和跳过数。单个申请人失败不阻断其他申请人；存在失败时调度任务记录为失败并保留各项汇总，便于当天手动重试。

## 邮件模板

在 SMTP 模板中新增 `ad_expiry_reminder` 场景，默认开启。默认主题为“GateRank 广告即将到期提醒（共 {{campaign_count}} 项）”。

默认邮件使用 HTML，内容包括：

1. 清晰的临期提示；
2. 临期广告列表，每项展示机场名称、广告位置、到期时间和剩余天数；
3. 指向站点 `/portal` 的“登录申请人后台”主按钮；
4. “登录后台 → 打开广告管理 → 选择广告续费并完成支付”的三步指引；
5. 无法显示 HTML 时使用的纯文本备用正文。

可配置变量包括：

- `{{campaign_count}}`
- `{{campaign_items}}`
- `{{portal_login_url}}`
- `{{applicant_email}}`
- `{{site_name}}`

后台保存的 HTML 由管理员控制；数据库动态字段在注入 HTML 前必须转义。`{{campaign_items}}` 只允许使用服务端生成的受控列表片段。纯文本备用正文由结构化广告数据生成，不依赖 HTML 剥离结果。

## 后台界面

在“系统设置 → 邮件场景与模板”的现有四列表格中新增“广告到期提醒邮件”一行，继续使用现有开关和“设置”入口，不新增独立页面或视觉组件。

视觉原则：保持现有白色/浅灰表面、轻边框、紧凑标题和次要说明层级；设置弹窗提示该模板支持 HTML，并展示可用变量。预览区域以安全方式渲染示例数据，不执行脚本或事件属性。

在“任务调度”中显示“广告到期提醒”，描述其按申请人合并发送临期广告通知。任务默认时间为 09:00，可沿用现有调度控件调整。

## 后台地址

申请人登录地址由现有站点 URL 配置生成并追加 `/portal`，不在数据库模板中硬编码生产域名。邮件按钮与纯文本正文使用同一个规范化地址。

## 兼容与迁移

- 现有 SMTP 配置读取时自动补齐新模板，不覆盖管理员已修改的其他模板。
- 调度任务表的枚举扩展为 `ad_expiry_reminder`，并通过现有 `INSERT IGNORE` 方式补充默认任务。
- 新发送记录表由仓储 `ensureSchema()` 幂等创建。
- 现有纯文本模板发送行为保持不变；只有新增广告到期提醒使用 HTML 与纯文本双正文。

## 验证

- 仓储测试覆盖北京时间 T-3、T-2、T-1，排除 T-0、T-4、已取消和已到期广告。
- 服务测试覆盖同一申请人多广告合并、不同申请人分别发送、每日去重、失败隔离和失败重试。
- 邮件测试覆盖 HTML 内容、动态字段转义、后台链接、续费指引、剩余天数和纯文本备用正文。
- SMTP 设置测试覆盖旧配置自动补齐与新模板开关。
- 调度测试覆盖新任务默认 09:00、任务执行分派、运行汇总和后台任务标签。
- 管理端静态测试覆盖模板行、HTML 提示和变量列表。
- 最终运行聚焦后端测试、完整后端测试、TypeScript 类型检查和生产构建；浏览器检查桌面与移动端模板表格及设置弹窗。

## 明确不包含

- 不发送到期当天或到期后的邮件。
- 不增加 Telegram、短信或站内信提醒。
- 不改变广告价格、续费规则、支付逻辑或广告到期语义。
- 不在本功能中重构现有其他邮件为 HTML。
