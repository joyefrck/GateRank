# GateRank 大陆多地区性能探针与按机场结果开关设计

日期：2026-08-08

## 1. 背景与问题

现有性能采集由单一中心执行，`airport_performance_runs` 虽然可以保存多次运行，但聚合阶段只读取机场当天最新的一条性能记录。单一测试位置会放大出口线路、测速目标、节点定向优化和测试机带宽的影响，无法回答“境外节点从中国大陆访问时实际表现如何”。

本次异常样本中，同一节点在当前测试位置重复出现约 1.7 Gbps，而此前相近节点约为 200 Mbps。现有计算按下载字节和耗时换算 Mbps，没有已确认的 8 倍单位错误；高值可以复现，但只代表单一节点、单一出口、单一测速目标的结果，不能代表机场整体，也不能单凭该值认定机场作弊。

GateRank 已准备两台腾讯云大陆探针：上海和广州，均为标称 200 Mbps 共享带宽。短时国内目标存在超过标称值的突发，跨境目标波动明显，因此探针结果必须有校准、多测速目标、带宽上限语义和影子运行，不能把一条瞬时结果直接替换现有评分。

## 2. 目标

- 增加上海、广州两个大陆性能探针，并保留现有中心探针作为对照。
- 每个机场可以分别配置每个测试地区是否执行测试、是否并入测试结果。
- 上海、广州先影子运行三天，不影响公开评分；切换必须由管理员确认。
- 原始测速值完整保存，评分规则按探针类型版本化，不回填历史成绩。
- 使用多目标和跨地区结果识别目标定向优化、位置差异与可疑异常，但不自动公开指控、不自动下架机场。
- 探针使用最小权限接口和独立令牌，泄露时可以单独撤销。

## 3. 非目标

- 不把 200 Mbps 共享带宽探针当作测量超高速节点极限吞吐的设备。
- 不以单次高值、地区差异或达到探针带宽上限直接判定作弊。
- 不在本次改造中回算历史性能分。
- 不把订阅链接、节点原始配置或探针令牌展示在后台、日志或公开接口。
- 不自动根据异常状态调整风险分、机场上架状态或公开排名资格。

## 4. 总体架构

系统包含三类角色：

1. **GateRank 中心服务**：刷新并保存订阅节点快照，生成探针任务，接收探针结果，执行校验、聚合、评分和异常分析。
2. **现有中心探针 `legacy-control`**：继续执行现有性能采集，使用原有评分口径，作为迁移期对照。
3. **大陆探针 `cn-shanghai`、`cn-guangzhou`**：通过受限接口领取节点快照任务，在本机完成测速并独立上传结构化结果。

中心服务是任务与配置的唯一事实来源。探针不能在上传内容中自行决定自己的 `probe_id`、测试是否参与评分或使用哪个评分规则；这些字段由令牌身份、任务快照和服务端配置共同确定。

### 4.1 数据流

1. 中心服务按现有流程刷新机场订阅并保存节点快照。
2. 调度器读取机场的地区配置，只为 `test_enabled=true` 的地区创建任务。
3. 探针通过 HTTPS 领取任务，校验本机状态并完成校准。
4. 校准通过后，探针对指定节点执行延迟、失败率和多目标并发下载测试。
5. 探针上传原始目标结果、节点级汇总和批次诊断。
6. 中心服务校验令牌身份、任务归属、配置版本和幂等键后保存结果。
7. 聚合器只读取该批任务快照中 `include_in_result=true` 且有效的地区结果。
8. 异常分析生成后台状态；公开页面只读取已批准的聚合结果和中性提示。

## 5. 数据模型

### 5.1 探针注册表

新增探针注册实体，至少包含：

- `probe_id`：稳定标识，如 `legacy-control`、`cn-shanghai`、`cn-guangzhou`。
- `display_name`、`region_code`、`provider`。
- `bandwidth_mbps`：探针标称带宽，上海、广州为 200。
- `probe_type`：`legacy` 或 `mainland`。
- `test_profile`：测试参数版本。
- `scoring_rule_version`：评分规则版本。
- `globally_enabled`：探针级总开关，仅用于运维停机，不替代机场配置。
- `token_hash`、`token_last_rotated_at`、`last_seen_at`；数据库不保存明文令牌。

### 5.2 按机场地区配置

新增 `airport_performance_probe_settings`，唯一键为 `(airport_id, probe_id)`：

- `test_enabled`：是否为该机场创建此地区的性能任务。
- `include_in_result`：此地区新采集结果是否参与该机场评分。
- `config_version`：每次保存递增，用于任务和结果快照。
- `updated_by`、`updated_at`。

必须满足：

- `include_in_result=true` 时，`test_enabled` 必须为 `true`。
- 关闭测试时同时关闭并入结果。
- 至少保留一个“开启测试且并入结果”的地区，否则拒绝保存，防止机场失去正式性能来源。
- 配置只影响保存后的下一轮任务；不改变已完成批次和历史成绩。

兼容默认值：

- 现有机场：`legacy-control` 为“开启测试、并入结果”。
- 上海、广州启用影子运行时：为“开启测试、不并入结果”。
- 新机场沿用同一默认策略，直到大陆方案完成正式切换。

### 5.3 性能任务与运行记录

任务需要保存：

- `job_id`、`airport_id`、`probe_id`、节点快照引用。
- `config_version`、`test_enabled_snapshot`、`include_in_result_snapshot`。
- `test_profile`、`scoring_rule_version`。
- 领取、租约、开始、完成、过期状态和幂等键。

扩展 `airport_performance_runs`，将下列内容保存为可查询的结构化字段，而不是只放在 `diagnostics` JSON：

- `job_id`、`probe_id`、`region_code`、`provider`、`bandwidth_mbps`。
- `run_mode`：`shadow` 或 `official`，来自任务配置快照。
- `test_profile`、`scoring_rule_version`、`config_version`。
- `calibration_status`、`calibration_mbps`。
- `review_status`：`normal`、`needs_review`、`suspicious`。
- 原有延迟、下载、失败率、节点可用性和节点明细继续保留。

新增目标级明细实体，按 `(run_id, node_key, target_key)` 保存下载值、耗时、字节数、HTTP/网络错误和有效性。这样才能区分节点快、测速目标快和探针出口快。

索引至少覆盖 `(airport_id, sampled_date, probe_id, sampled_at)`、`job_id` 和异常状态查询。旧记录映射为 `legacy-control`，保持旧接口和旧数据可读。

## 6. 测试配置与校准

### 6.1 大陆测试配置

大陆探针使用版本化配置 `mainland_multi_target_v1`：

- 延迟使用节点建连延迟，代理 HTTP 延迟仅作诊断。
- 下载使用多个彼此独立、明确允许测速的目标；每个目标使用相同文件规模、超时和并发设置。
- 每个节点保留各目标原始值，节点代表值取有效目标结果的中位数。
- 地区代表值取该地区有效节点代表值的中位数。
- 失败率按代理请求失败次数 / 总尝试次数计算，保留失败原因分组。

测试目标属于版本化服务端配置，不在探针上临时硬编码。目标变更必须产生新的 `test_profile` 版本，避免不同日期的数据口径不明。

### 6.2 校准

每批正式节点测试前执行独立的国内基线校准：

- 校准结果低于 160 Mbps 时，本批标记为 `calibration_failed`，不得参与聚合。
- 校准通过不证明后续节点速度准确，只证明探针在该时段具备最低测试能力。
- 单一测速目标在同期大量机场上普遍下降时，优先标记目标或路径故障，不把异常归因于机场。
- 校准和节点测速使用不同目标，防止同一目标故障同时污染基线与业务结果。

## 7. 聚合与评分

### 7.1 完整批次要求

对某机场某日期，中心服务从任务配置快照取得需要参与评分的地区集合。只有所有应参与地区都存在校准通过、状态有效且配置版本匹配的结果时，才生成当日新的正式性能聚合。

如果任一应参与地区缺失或失效：

- 不静默减少地区数量，不临时只用最快或可用地区重算。
- 当日显示“等待完整地区数据”。
- 保留上一份有效公开成绩，后台展示缺失地区和失败原因。

影子地区的失败不会阻断正式评分，但必须在后台影子状态中可见。

### 7.2 分地区评分，再等权合并

不同探针类型使用不同评分规则。为避免先混合原始 Mbps 后无法选择阈值，先在地区内计算组件分，再对纳入结果的地区等权合并：

1. 每个地区分别得到 `LatencyScore`、`SpeedScore`、`LossScore`。
2. 每个地区计算 `P_region = 0.4 * LatencyScore + 0.4 * SpeedScore + 0.2 * LossScore`。
3. 所有纳入地区的三个组件分和 `P_region` 分别取等权平均，得到当日正式性能组件和 P 分。
4. 用于后台解释的原始延迟、下载和失败率取各地区代表值的中位数；原始展示值不替代地区分数聚合。

这样每个地区只有一票，不会因某地区节点数、目标数或重试次数更多而获得更高权重，也允许迁移期同时纳入不同规则版本。

### 7.3 评分规则版本

现有中心探针继续使用原规则：

```text
SpeedScore = clamp((median_download_mbps - 10) / (300 - 10) * 100, 0, 100)
```

大陆探针使用 `cn_dual_probe_v1`：

```text
SpeedScore = clamp((median_download_mbps - 10) / (160 - 10) * 100, 0, 100)
```

- 10 Mbps 及以下为 0 分。
- 160 Mbps 达到大陆探针速度满分。
- 原始值仍完整保存，不把 160 或 180 写回原始值。
- 180 Mbps 及以上增加 `probe_ceiling` 标记，后台显示“≥180 Mbps，达到探针带宽上限”，不宣称精确极限速度，也不因此判定作弊。
- 延迟、失败率和 P 权重保持现有口径。
- 规则版本随每条运行记录保存；不回算历史记录。

## 8. 异常分析

异常分析与正式评分分离，先产生证据状态，不直接改变分数或上架状态。

### 8.1 规则

- **目标差异**：同一探针、同一节点、同一批次中，最快目标超过最慢有效目标 3 倍，且最快值超过 100 Mbps，标记目标差异。
- **地区差异**：上海与广州同一节点代表值相差超过 3 倍，且较高值超过 100 Mbps，标记位置差异。
- **中心与大陆差异**：现有中心结果超过大陆代表结果 3 倍，且中心结果超过 300 Mbps，标记对照差异。
- **探针上限**：大陆结果达到 180 Mbps 只标记 `probe_ceiling`，不是异常证据。
- **探针失准**：校准低于 160 Mbps，整批无效。
- **目标群体故障**：同一目标在同期大量机场、多个节点上共同退化时，归类为目标或网络路径问题，不累计机场可疑证据。

### 8.2 状态

- `normal`：没有满足复核规则。
- `needs_review`：单日出现一个独立异常维度。
- `suspicious`：同一异常连续两天成立，或同一天出现两个相互独立的异常维度。

状态只用于后台复核。公开页面最多显示“不同测试地区结果差异较大，正在复核”，不得使用“作弊”“造假”等未经人工确认的定性措辞。

## 9. 管理后台

本功能是所有机场共用的能力，配置粒度为“机场 × 测试地区”。在机场数据工作台的“性能数据（P）”页，于“评分公式”和“性能测试节点”之间新增“测试地区配置”卡片。

### 9.1 地区行

每个地区一行，展示：

- 地区名称、探针类型和最近一次采集时间。
- 最近校准状态、运行状态和异常状态。
- “开启测试”开关。
- “并入测试结果”开关。
- 状态文案：`参与评分`、`影子测试`、`已停用`、`等待完整地区数据` 或 `探针不可用`。

初始状态示例：

| 测试地区 | 开启测试 | 并入测试结果 | 状态 |
| --- | --- | --- | --- |
| 现有中心对照 | 开 | 开 | 参与评分 |
| 上海 | 开 | 关 | 影子测试 |
| 广州 | 开 | 关 | 影子测试 |

### 9.2 交互规则

- 开关先修改本地草稿，由统一的“保存地区配置”提交，避免误触即改变后续评分。
- 有未保存修改时显示提示；保存中禁用重复提交。
- 关闭“开启测试”时同步关闭该行“并入测试结果”。
- 测试关闭时禁用“并入测试结果”开关。
- 开启并入结果前，接口校验最近校准是否正常；未通过时拒绝并解释原因。
- 修改并入范围时显示确认提示：“配置将从下一轮性能采集生效，不修改历史成绩”。
- 保存成功写入现有审计日志，记录管理员、机场、修改前后值、请求 ID 和时间。
- “重新采集并重算性能”和定时调度共用同一配置读取逻辑。
- 选择历史日期时只读展示该日期运行记录中的配置快照；仅当天页面可以修改当前运行配置。

视觉沿用 GateRank 管理后台：白色卡片、细边框、紧凑排版、近黑主操作和靛蓝语义状态；不增加装饰性大色块。开关必须支持键盘、明确焦点态、文本标签和至少 40px 的触控区域，不能只靠颜色表达开关状态。

### 9.3 地区结果展示

“最近一次性能采集”按地区分组，而不是只展示最新一条全局记录。每组可展开查看：

- 校准、测速配置和规则版本。
- 节点级结果、目标级结果与地区代表值。
- 是否参与本轮聚合。
- 失效、缺失或异常原因。

原有聚合指标继续在顶部展示，并明确标注本轮参与地区。

## 10. API 与权限

### 10.1 管理接口

新增按机场读取和保存地区配置的管理员接口，沿用现有后台认证、请求 ID、校验和审计能力。更新接口应支持乐观并发控制，提交旧 `config_version` 时返回冲突，防止两个管理员互相覆盖。

### 10.2 探针接口

探针只使用专用接口：

- `GET /api/v1/performance-probe/jobs`：领取与本令牌绑定地区的待执行任务。
- `POST /api/v1/performance-probe/runs`：按任务上传结果。

安全边界：

- 每台探针使用不同的高熵令牌，服务端仅保存哈希。
- 服务端根据令牌绑定确定 `probe_id`，忽略或拒绝客户端伪造身份。
- 任务使用短租约和一次性/幂等提交键，重复上传不得创建重复正式结果。
- 接口启用速率限制、请求体大小限制、严格 schema 校验和合理时钟偏差校验。
- 任务只返回执行所需的最少节点快照；订阅链接和节点配置不得进入日志或错误消息。
- 探针令牌不能访问管理员接口、机场管理、排名数据或其他探针任务。
- 令牌可单独吊销和轮换，不使用全局 `ADMIN_API_KEY`。

## 11. 探针部署

上海、广州仅部署独立探针程序：

- 路径 `/opt/gaterank-probe`。
- 专用系统用户 `gaterank-probe`，禁止交互登录。
- Python 虚拟环境和锁定版本依赖。
- `sing-box` 使用固定版本和校验和，不从不受信任位置动态下载执行。
- 环境文件权限 `0600`，只保存该探针自己的受限令牌和中心 API 地址。
- 使用 systemd service/timer 或等效长期任务管理；同一探针默认单任务串行，避免 1 GB 内存和共享带宽上的并发互相污染。
- journald/应用日志只记录任务 ID、机场 ID、阶段、耗时、状态和错误码，不记录秘密或原始节点配置。
- 为下载文件、临时配置和核心进程设置超时、大小上限与可靠清理。

部署期间先保留现有 SSH 登录方式。新 SSH 密钥验证成功后再更换已暴露密码并考虑关闭密码登录，避免远程锁死；凭据不写入仓库、设计文档或命令日志。

## 12. 发布与切换

### 阶段 0：兼容改造

- 上线向后兼容的数据表、字段、接口和聚合逻辑。
- 旧记录映射为 `legacy-control`，现有机场默认评分不变化。
- 探针注册为全局停用，确认迁移和旧流程无回归。

### 阶段 1：单机场联调

- 仅为 Now 加速开启上海、广州测试，不并入结果。
- 验证订阅快照、任务领取、校准、节点测速、幂等上传、后台地区展示和秘密清理。
- 明确验证当前公开 P 分及其他机场结果不受影响。

### 阶段 2：全量影子运行三天

- 为全部可运行机场开启上海、广州测试，保持“不并入结果”。
- 使用串行任务和错峰调度控制探针资源。
- 每日检查两个大陆地区的任务完整率、校准通过率、目标健康度、地区差异和错误分布。
- 影子失败只告警，不影响当前正式评分。

### 阶段 3：人工切换

- 三天数据完整且校准稳定后，管理员按机场或通过受审计的批量操作开启上海、广州“并入测试结果”。
- 现有中心探针是否继续并入由管理员明确选择；建议切换为大陆双地区正式、中心仅对照。
- 不自动切换，不回算历史成绩。

### 阶段 4：持续观察

- 观察至少一个完整调度周期的任务完整性、评分变化、异常状态和公开页面。
- 记录规则版本和切换时间，便于解释评分断点。

## 13. 回滚

- 单机场异常：关闭对应地区“并入测试结果”，下一轮恢复其他正式地区；必要时同时关闭测试。
- 单探针异常：设置探针全局停用并吊销令牌，不影响另一探针和中心服务。
- 新聚合逻辑异常：恢复仅 `legacy-control` 参与评分，保留多地区原始记录供排查。
- 安全事件：吊销单台令牌、停止服务、轮换令牌；无需更换全局管理员凭据。
- 数据库改造采用向后兼容新增字段/表，回滚应用时不删除原始数据。

回滚不得重写已经公开的历史日记录；所有开关变化和运维动作保留审计轨迹。

## 14. 验证与验收

### 14.1 自动化验证

- 数据库迁移、旧记录兼容和索引测试。
- 地区配置约束、乐观锁、审计和默认值测试。
- 探针令牌隔离、伪造 `probe_id`、越权、幂等与重复提交测试。
- 开关组合测试：开/并入、开/不并入、关/不并入，以及非法关/并入。
- 缺少一个正式地区、校准失败、任务过期和部分上传时不生成新正式聚合。
- legacy 300 Mbps 与 mainland 160 Mbps 两套评分规则版本测试。
- 多地区等权测试，确保节点数、目标数和重试数不会改变地区权重。
- 180 Mbps 上限标记、三类差异规则、连续两日和双维度异常状态测试。
- 后台地区配置、历史只读、保存确认、键盘操作和错误提示测试。

### 14.2 线上验收

- Now 加速影子运行时，公开 P 分与上线前保持一致。
- 上海、广州都能独立领取、完成和上传任务，后台可追溯任务 ID、地区和规则版本。
- 日志、接口错误、进程参数和临时目录中找不到订阅链接、节点原始配置、令牌或登录密码。
- 校准低于 160 Mbps 时该地区整批不进入聚合。
- 任一正式地区缺失时保持上一份有效成绩，并准确提示缺失原因。
- 手动重测与定时任务读取相同地区配置。
- 切换上海、广州并入后，只从下一轮产生新口径评分，历史日期不改变。
- 关闭开关、停用探针或吊销令牌能够按预期回滚，中心旧流程仍可运行。

## 15. 实施边界

设计文档批准后再编写逐文件实施计划。实现顺序应为：数据模型与兼容读取、配置与探针 API、任务与探针执行器、地区聚合与版本化评分、异常分析、后台 UI、自动化验证、单机场部署、三天影子运行、人工切换。任何生产服务器写入、探针安装或评分切换都必须在相应代码与回滚验证就绪后执行。
