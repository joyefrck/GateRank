# 订阅节点 DNS 保留与探测修复

用户在生产对照诊断后授权“开始修复”。同一生产快照的香港专线02、美国直连01、日本直连02使用系统 DNS 失败，使用订阅专用 DNS 返回地址的代理 HTTPS 检查成功。

## 方案

将 `dns.proxy-server-nameserver` 和 `dns.ipv6` 作为可选节点元数据保存到已有 `nodes_json`，不改节点身份或历史快照。后端输入校验、仓库读写及探针任务下发保留元数据。无专用 DNS 的旧快照继续使用系统 DNS。

使用 dnspython 解析专用 DNS，支持 IP DNS、UDP/TCP、TLS 与 HTTPS；查询有时间上限，配置只作用于所属节点。解析结果逐地址尝试 TCP，成功地址只在临时代理配置中使用，同时保留 TLS server_name 和 Reality 参数。原始域名、URI、节点 key 不变。专用 DNS 失败时不退回可能错误的系统 DNS。

保存解析结果仅限一次探测过程；后续任务重新解析，避免长期固定节点 IP。IPv6 禁用设置生效。失败保持不可用，成功仍必须完成真实代理 HTTP 检查。

## 验证与发布

回归覆盖订阅解析、快照往返、后端读写和任务下发、专用 DNS 超时及多 IP 回退、临时代理配置与 SNI。运行 Python 和后端全量回归、类型检查、构建；提交当前 main 并等待对应镜像 CI。备份后更新 Web/API 和上海、广州探针，刷新光速云快照并采集两地真实网络覆盖，核对后台与公开报告。

## 范围

不改变评分公式、节点 key、用户节点选择或其他机场 DNS。订阅中的规则分流、节点链式代理和域名 DNS policy 不在本次修复范围。生产探针通过现有 Termius 连接操作，不导出凭据。
