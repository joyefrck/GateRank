# GateRank 首页卡片运行天数与趋势说明设计

## 背景

首页“今日推荐机场”卡片在紧凑布局改造后保留了价格、昨日变化、标签和 30 天评分折线，但遗漏了服务层已经提供的“运行天数”，折线区域也缺少可见标题。新用户难以判断折线表达的指标与时间范围。

## 已确认方案

采用方案 A：在标签和折线之间增加一条紧凑信息行。

- 左侧固定显示“近 30 天评分趋势”。
- 右侧显示“已运行 {天数}”，例如“已运行 64 天”。
- 运行天数直接复用 `HomeCardItem.details` 中 `label === '运行天数'` 的真实值，不新增接口、不重复计算。
- 如果旧缓存或异常数据缺少运行天数，右侧显示“运行天数待补充”，不伪造天数。
- 趋势数据存在时继续绘制当前线性折线；缺少趋势时标题仍保留，折线区域继续显示“暂无趋势”。

## 布局与视觉

- 信息行位于最多 3 个标签下方、折线图上方。
- 标题和运行天数使用 10px–11px 的辅助信息层级，标题深于运行天数，避免与机场名称、评分和按钮争夺注意力。
- 卡片统一增加必要的最小高度，保留现有折线高度和双按钮点击区域，不通过压缩图表或按钮补偿新增内容。
- 手机端保持 86vw 横向吸附卡片，信息行单行显示；过长运行天数文本不换行。

## React 与 SSR 一致性

- React 首页从 `item.details` 读取运行天数并渲染信息行。
- SSR 公开页渲染器输出相同标题和运行天数；SSR 趋势正文继续提供首尾分数与数据点数量。
- 现有官网外链追踪、点击计费、测评链接、标签数量、图表数据和排序逻辑均不变。

## 可访问性与安全降级

- 折线容器现有 `role="img"` 与包含机场名称、时间范围和数据点数量的 `aria-label` 保持不变。
- 可见标题不依赖颜色表达含义。
- 缺少运行天数或趋势数据时使用明确文字，不输出空白占位或虚构数据。

## 验证

- React 源码回归：使用 `details` 中的“运行天数”，显示“近 30 天评分趋势”，保留 `slice(0, 3)`、黑色官网按钮和外链追踪。
- SSR 路由回归：可抓取“近 30 天评分趋势”和“已运行 64 天”；缺失运行天数时输出“运行天数待补充”。
- 服务层既有测试继续验证今日推荐返回“运行天数”。
- 运行聚焦测试、`npm run lint`、`npm run server:typecheck`、`npm run test:backend`、`npm run build`。
- 在 1440px 与 390px 浏览器视口检查信息行、卡片等高、按钮和整体横向溢出，并更新 `design-qa.md`。

## 范围

- 仅修改首页“今日推荐机场”卡片及对应 SSR。
- 不修改其他榜单卡片、不新增 API 字段、不修改机场运行天数计算方式、不部署生产环境。
