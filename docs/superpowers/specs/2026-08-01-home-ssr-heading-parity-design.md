# GateRank 首页 SSR 与客户端标题一致性设计

## 目标

统一首页服务端可抓取 HTML 与 React 客户端渲染后的三个 H2 标题，避免搜索引擎、轻量爬虫和 AI reader 因渲染方式不同而获得不同的页面语义。最终文本以前端当前展示为准。

## 已确认范围

- SSR “今日赞助推荐”改为“商业合作专区”。
- SSR “综合实力排行”改为“🏆 GateRank 排行榜”。
- SSR “最新 News”改为“公告与动态”。
- React 首页标题保持不变。
- 各区块的英文眉题、副标题、链接、结构、数据和样式保持不变。
- 不修改 `gaterank-3.0/` 旧原型；当前生产实现以 `src/pages/home/HomePageV3.tsx` 和 `backend/src/services/publicPageRenderer.ts` 为准。

## 实现方案

在 `backend/src/services/publicPageRenderer.ts` 中直接替换三个静态 H2 文案。标题数量少且只在首页使用，因此不引入新的跨端共享常量或渲染依赖，避免扩大改动范围。

更新 `backend/tests/publicPageRoutes.test.ts` 的首页契约断言：确认三个新标题存在，并确认三个旧标题不再出现在服务端 HTML 中。前端源代码契约测试继续证明 React 侧使用目标文案，使两条渲染路径均受到回归保护。

## 兼容与风险

- 标题元素、ID 和 `aria-labelledby` 关系不变，辅助技术关联不受影响。
- 只改变可见文本，不影响数据加载、水合、导航或页面布局。
- “🏆”作为目标前端标题的一部分同步进入 SSR，确保文本完全一致。
- 页面其它位置若存在描述性“综合实力排行榜”文本，例如表格 caption，不属于这三个 H2，不做替换。

## 验证

- 运行首页 SSR 路由测试，验证新旧标题的正反向断言。
- 运行前端可抓取内容契约测试，验证 React 标题仍为目标文案。
- 运行相关类型检查或生产构建，确认静态模板修改未引入编译问题。
- 执行 `git diff --check`，检查补丁格式。
