# 首页加载性能优化方案

## 目标与边界

降低首页首次加载的资源与主线程开销，保留首屏排行榜、核心内链、完整 SSR 内容、SEO 元数据及广告曝光/点击统计。沿用当前 main，不更改业务评分、计费或页面布局。本阶段为本地实现与验证；生产发布另行执行。

## 已核实的现状

- 用户报告：TTFB 331 ms、FCP 2320 ms、DOMContentLoaded 2623 ms、Load 3649 ms。尚未在相同设备和缓存条件下复现这些时间。
- 线上版本 38fa85636bda5d323b20029078f4f1d77828ce4a：首页入口 JS 988783 字节、CSS 233726 字节；本地 gzip 估算分别为 290188、35232 字节，非浏览器实际传输量。
- `src/main.tsx` 静态导入 `src/App.tsx`；后者静态导入多种工具、报告及商户页面。
- IPCheckPage 静态引用 IpCheckMap，后者静态导入 Leaflet 和地图 CSS。
- `src/index.css` 顶部通过远程 CSS @import 引入 Google Fonts，增加外部样式依赖。
- React 使用 createRoot 接管手写 SSR；首页标题、指标与排行榜行均有初始透明入场动画。
- 首页线上 HTML 约 181 KB，内联样式约 90 KB，未发现 img 元素。不能据此把图片认定为瓶颈。
- 商业合作和 News 已包含于首页数据，无需为懒加载再制造请求瀑布。

## 推荐方案

1. 为首页提供独立轻量入口；非首页 App 按路由需求动态加载。保留日期参数、前进后退、站内导航、页面浏览和广告统计行为。入口加载期间保留现有 SSR，避免空白替换；不直接将手写 SSR 改为 hydrateRoot。
2. 地图库及其样式只随 IP 查询功能加载，验证首页静态依赖图中不再出现该模块。
3. 去除全局远程字体 @import 的阻塞链，优先使用当前系统字体回退；如保留远程字体，则以非阻塞方式加载，并检查中英文排版及布局变化。
4. 首屏标题、指标和排行榜默认可见，保留必要的悬停/交互反馈。
5. 商业合作、工具、News 和下方介绍保持 SSR 内容与真实链接，优先使用 content-visibility 等浏览器延迟布局能力。曝光统计仍以真实进入视口为准；避免隐藏 SSR 或首次渲染移除内容。

## 备选与取舍

- 仅取消首屏动画和调整字体：改动最小，但无法消除非首页 JS 的下载和解析成本。
- 推荐的入口拆分加渲染优化：针对已确认的资源问题，保留当前功能和视觉结构。
- 全量迁移为 React SSR 与分区 hydration：涉及所有页面模板和路由，超出本次性能修复范围。

## 验证

- 使用独立临时构建目录记录改动前后的首页静态依赖总字节及 gzip 估算，保护当前已有 dist 修改。
- 检查首页、日期筛选、排行榜跳转、历史导航、商户入口、工具页、广告点击与曝光；桌面和移动端均保留核心内容且无明显布局偏移。
- 检查 SSR 排行榜、News、商业合作与工具链接及 JSON-LD 不被移除。
- 运行相关前端链接/SSR/资源测试、TypeScript 检查与生产构建。
- 相同浏览器、网络和缓存条件下比较 FCP、DOMContentLoaded、Load；开发服务器时间不作为生产改进证明。没有生产复测时，只报告本地验证与资源减少量。
