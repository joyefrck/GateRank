# IP 纯净度检测

公开入口：`/tools/ip-purity-check`。后台入口：`/admin/ip-purity`。

## 功能与数据

- 当前出口自动查询、手动公网 IPv4 / IPv6 查询、复制地址、错误后重试。
- ipwho.is 复用现有 IP 查询服务，提供归属地、ISP、组织和 ASN。
- proxycheck.io v3 提供风险分数，以及代理、VPN、Tor、机房四项信号；只提取这些辅助字段，不公开原始 API 响应。
- 使用供应商原始 0–100 风险分数，不转换为“纯净百分比”。界面分段为 0–25 低风险、26–50 需关注、51–100 高风险。分数不是平台封禁概率，也不与 ping0 保持一致。
- 原生 IP 接入 IPOK 直接标签及 RIPE NCC 注册国家证据：有直接标签优先展示；标签未知时对比注册国家和定位国家，显示原生倾向或跨区使用倾向。来源冲突时保留分歧。共享人数暂不支持检测；未检测到机房不推断成家庭宽带。
- 风险或归属地服务独立降级。缺失字段为未知；上游失败不视作 0 分。

## 服务器配置

在 API 进程的环境中配置；Docker 部署需要将变量传入容器。

```dotenv
IP_PURITY_API_KEY=
IP_PURITY_DAILY_LIMIT=100
IP_PURITY_TIMEOUT_MS=5000
IP_PURITY_CACHE_TTL_MS=3600000
```

proxycheck.io 匿名免费额度为每来源每日 100 次；注册免费账号后可使用自有 Key（官方目前为每日 1,000 次）。设置 Key 后，将预算同步调整到实际套餐；不在浏览器、SEO 配置或仓库内保存 Key。未显式设置每日预算时，无 Key 默认 100，有 Key 默认 1,000。

本地预算按 API 进程、UTC 日重置；重启会清空，多个进程各自计数，上游仍执行账户/来源总额度。高并发或多实例部署应使用匹配的付费额度及统一额度管理。风险缓存最多 1 小时、2,000 条；基础地理缓存延用现有 24 小时策略。请求合并与每客户端 15 分钟 30 次限流减少重复查询。上游 429 后暂停风险请求至少 60 秒。

查询目标和结果不写入业务数据库；IP 传递给上述供应商。若反向代理未提供公网出口，页面会尝试 ipify 浏览器回退；需要手动输入时会明确提示。

## 原生判定来源与边界（2026-09-05 补充）

- IPOK 官方接口 `https://ipok.io/api/ip?ip={ip}` 提供 `nativeType`（native/broadcast/unknown）。公开指定目标额度为 15 次/日，本实现遵守该预算并缓存标签 1 小时；429 遵守 Retry-After。按要求在页面提供 IPOK 署名与回链。只使用原生字段，不转发全量数据。
- RIPE NCC 官方接口 `https://stat.ripe.net/data/rir/data.json?resource={ip}&lod=2` 提供 RIR 分配记录。按查询 IP 验证响应，选取实际包含目标的最具体网段，读取国家、注册局、网段和快照日期；同级国家冲突不产生结论。不读取联系人信息。
- RIPE 注册国家缓存 24 小时，两来源独立失败；每个进程最多 4 个并发原生证据查询，缓存总计最多 2,000 条。API 请求超时 4.5 秒，与风险和定位请求并行。
- “原生倾向 · 注册地一致”仅表示 RIR 分配国家与地理定位国家一致，不是验证物理路径或保证平台可用。不能把 ASN 运营商名称或低风险分数当作原生证明。
- 真实样本 AT&T 出口：IPOK 返回 unknown，RIPE 记录为 ARIN、US、162.224.0.0/12，定位为 US，得到注册地一致性参考。
- 参考文档：https://ipok.io/developers 、https://ipok.io/methodology 、https://stat.ripe.net/docs/data-api/api-endpoints/rir 。
